# Перенос 3D-ресурсов из Git в локальную work-папку

Обновлено: 16 октября 2026. Цель владельца: 3D-модели и Blender-исходники хранить локально; в Git оставлять код, конфигурацию и манифесты. Это правило пока выполнено только для новых островных моделей и новых корабельных моделей в `work/`, но не для всего исторического набора.

## Инвентаризация

- В текущем Git индексе находится **491 файл / 219 001 440 байт (около 209 MiB)**: 361 `.glb` и 130 `.blend`.
- Самые крупные семейства: 168 расовых кораблей в `assets/world/ships/factions/`; 217 моделей уровней семи зданий (по 31 на здание); остальные — отдельные торговые/боевые корабли, уровни построек, детали зданий, стили, портовые объекты, растительность и источники.
- Известные манифесты с прямыми путями: `data/world/world_asset_catalog.json`, `data/world/ship_visuals.json`, `data/world/faction_ship_visuals.json`, `data/world/home_base_visuals.json`, а также каталоги архитектуры и отдельных игровых систем. Перед переносом нужен полный поиск всех файловых загрузчиков, не только JSON.
- Новая «Кристальная Эгида» уже показывает целевой подход: код может ссылаться на `res://work/...`, загрузить GLB напрямую, а при отсутствии локального файла оставить процедурную модель. Копия без `work/` должна запускаться с fallback.

## Безопасный порядок миграции

1. Составить машинную таблицу `tracked path → runtime references → category → fallback → local destination`; отделить редактируемые `.blend` от загружаемых `.glb`.
2. Убедиться, что модели и внешние зависимости сохранены в локальной `work/assets/...` с понятной структурой и резервной копией. Ничего не удалять из исходной папки до сверки размеров и хешей.
3. Для каждой категории подключить локальную загрузку и явный fallback: корабли, уровни зданий/детали, портовые и природные объекты, персонажи/декор. Проверить старт, посещение портов, строительство/улучшение, окна предпросмотра и ошибки отсутствующего файла.
4. Проверить две конфигурации: с полной локальной `work/` — показываются модели; без неё — проект открывается и работает без ошибок, используя процедурные/векторные заглушки.
5. Только после проверки удалить старые файлы из Git-индекса и добавить надёжное правило игнорирования локальных 3D-файлов. Не включать в очистку чужие пользовательские картинки и не менять игровую геометрию/сохранения.

## Ограничения и замечания

- Массовое удаление 361 GLB сейчас небезопасно: многие пути напрямую перечислены в каталогах и могут не иметь полноценной замены. Не считать островные GLB единственными файлами, которые ещё попадают в репозиторий.
- Политика хранения исходников `.blend` и runtime-экспортов `.glb` одна: оба формата должны оставаться локально. Но мигрировать их нужно раздельно, потому что `.glb` загружаются игрой, а `.blend` нужны художнику.
- В соседней рабочей копии могут присутствовать локальные правки. Перед пакетной миграцией сначала сверить `git status`; не затрагивать незакоммиченные файлы вне выбранного списка.
