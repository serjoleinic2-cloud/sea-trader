# Где менять параметры и как добавлять механику

## Карта проекта

| Папка | Что хранится |
| --- | --- |
| `data/` | Настройки и определения. Здесь меняется баланс, а не сохранённый прогресс. |
| `autoloads/` | GameState, SaveSystem, EventBus, GameData. |
| `core/` | Проверка конфигурации и подключение модулей. Здесь нет игровой экономики. |
| `systems/<область>/` | Правила конкретной механики: торговля, строительство, челленджи и т. д. |
| `systems/ui/` | Отображение данных и команды игрока. |
| `scenes/` | Состав сцен, визуальные узлы и камера. |
| `assets/` | Изображения, звук, шрифты. |
| `tests/` | Модульные проверки и запуск полной сцены. |
| `rules/` | Текущие решения, инструкции и отдельно обозначенные планы. |

## Параметры

| Что изменить | Файл | Основные поля |
| --- | --- | --- |
| Корабль | `data/ships/ship_catalog.json` | `base_speed`, `cargo_capacity`, `fuel_capacity`, `min_crew`, `max_crew`, `command_rank_required` |
| Разгон, торможение, поворот, расход топлива | Тот же каталог | `defaults.acceleration`, `brake_force`, `turn_rate`, `fuel_per_second`; любой корабль может переопределить значение |
| Материалы верфи | Тот же каталог | `ships[].build_materials` |
| Название и максимальный уровень здания | `data/ports/building_catalog.json` | `display_name`, `max_level` |
| Материалы и сроки зданий | `data/ports/building_rules.json` | `base_materials`, `additional_materials`, `growth_per_level`, `duration_*`, `rank_gates` |
| Производство | `data/ports/production_recipes.json` | Здание, ресурс, выпуск, минимальный уровень, `cycle_seconds` |
| Товары и базовая цена | `data/resources/goods_catalog.json` | `id`, `display_name`, `category`, `base_price` |
| Доставка | `data/economy/market_rules.json` | `delivery_surcharge`, `delivery_seconds` |
| Заправка и ремонт | `data/ports/service_rules.json` | Цены услуг, выход топлива/ремонта из материалов, скидка мастерской |
| Активный автопилот | `data/economy/logistics_rules.json` | Скорость, расход на расстояние, радиус прибытия |
| Карьера | `data/progression/career_ladder.json` | Профессии, пороги, веса активности |
| Персонал | `data/employees/hiring_rules.json` | Профессии сотрудников, зарплаты, названия характеристик |
| Челленджи | `data/challenges/challenge_rules.json` | Сроки, цели, сложность, период повторного получения, награда |
| Бусты, премиум, артефакты | `data/rewards/reward_catalog.json` | Эффекты, длительности, части, ограничения бонусов |
| Мир | `data/world/world_gen_config.json` | Размеры, острова, порты, опасности; учитывать версию генератора |
| Модули и кнопки навигации | `data/config/game_modules.json` | Скрипт, зависимости, окно, кнопка |

Другие прототипные формулы (события, потребление компании, предложения торговцев) остаются в своих системах. Не добавлять новый баланс в UI; переносить нужную формулу в тематическую конфигурацию при развитии механики.

## Пример: изменить лодку

В `ship_catalog.json` найти объект с `id: "ship_sloop"`. Изменить `base_speed` или `cargo_capacity`. Общие значения находятся в `defaults`; поля внутри конкретного корабля имеют приоритет. Перезапустить игру.

Физика, верфь, найм и флот читают один каталог. Отдельные старые `ship_sloop.json`, `fleet_catalog.json`, `crew_requirements.json`, `ship_build_recipes.json` удалены. Неиспользуемые проектные цели из `ship_tiers.json` перенесены в `rules/design/ship_tier_goals.json` и помечены как планы; игра их не читает. Долгосрочное развитие описано в `LONG_TERM_PROGRESSION.md`.

Вместимость выражена в единицах товара, а не в весе. `weight_per_unit` пока не используется как ограничение трюма.

Новые лодки используют вместимость 50 — значение существующего активного корабля. Старые суда флота с трюмом 20 сохраняют своё значение. Позиция, повреждения, топливо, груз и индивидуальные улучшения сохранённого судна не перезаписываются каталогом. Для массового изменения уже созданных экземпляров нужна явная миграция, а не сброс сохранения.

Экономический баланс теперь находится в `data/economy/balance_rules.json`: целевые запасы,
потребление, разница цен покупки/продажи, расходы вспомогательного флота, резерв производства
и оплата работы. Чистые расчёты — `systems/economy/economy_model.gd`; они используются игрой
и симулятором. После изменения коэффициентов выполните обычные тесты и
`bash tests/economy/run_simulation.sh`. Не возвращайте отдельные формулы цены в UI.

## Добавить корабль

1. Добавить объект в `ship_catalog.json`: уникальный `id`, русское `name`, `tier`, допуск, физические параметры, экипаж и `build_materials`.
2. Использовать существующие ID товаров или сначала добавить их в каталог товаров.
3. Каталог верфи и лимиты найма обновляются автоматически. Новая модель/сцена отдельно нужна только при отличающемся визуале; переключение ручного управления на любой корпус пока не реализовано.
4. Проверить допуск, проект, материалы, постройку и сохранение. Не переименовывать ID уже выпущенных кораблей без миграции.

## Добавить игровой модуль

Создать `systems/<область>/<имя>_system.gd`. Класс наследуется от `Node`; зависимости получает через `initialize(...)`, а не через обход дерева UI. Пример:

```gdscript
extends Node

var _ports: Node

func initialize(ports: Node) -> void:
    _ports = ports

func get_summary() -> String:
    return "Известных портов: %d" % GameState.player_state.discovered_port_ids.size()
```

Добавить запись в `data/config/game_modules.json`:

```json
{
  "id": "ExpeditionSystem",
  "script": "res://systems/expeditions/expedition_system.gd",
  "initialize": "initialize",
  "args": ["PortSystem"]
}
```

`args` содержит имена модулей в порядке аргументов метода. Внешние зависимости: `$ship`, `$ports` (словарь сгенерированных портов), `$main`. `after` задаёт дополнительные зависимости запуска без передачи аргументов. Загрузчик сортирует зависимости, отклоняет неизвестные имена, повторы и циклы; проверяет наличие скрипта и сигнатуру инициализации до загрузки игровых систем.

Модули принадлежат сцене Main и удаляются вместе с ней. Доступ снаружи — `main.get_module("ExpeditionSystem")`. Поле `bind` сохраняет старые ссылки Main для совместимости; **новому модулю оно не нужно**, менять `main.gd` для его подключения не требуется.

## Добавить окно модуля

Окно — `CanvasLayer` с `_panel: PanelContainer`, `_open: bool` и `open()`. Создать содержимое панели в `_ready()`, зависимости принять через `initialize()`. Добавить в запись модуля:

```json
{
  "workspace_flag": "_open",
  "navigation": {"label": "Экспедиции", "method": "open", "order": 60}
}
```

WindowCoordinator сам добавит закрытие, прокрутку и кнопку навигации. Он закрывает предыдущее окно и скрывает дублирующий HUD. Новую механику без собственного главного окна лучше открывать из существующего раздела: не накапливать бесконечный ряд кнопок.

## Данные и сохранения

- Статические данные: `GameData.read("res://data/...json")`; корабли — `GameData.get_ship(id)`. Возвращаются копии, исходный каталог нельзя случайно изменить через ссылку.
- Состояние игрока: `GameState`. Локальные поля Node допустимы для ссылок, кэшей и визуального состояния, но не для единственного экземпляра прогресса.
- Диск: только `SaveSystem`. Новый верхний раздел требует обновления сериализации, восстановления и миграции. Новые вложенные разделы существующего состояния получают значения по умолчанию через `get()`.
- UI: только чтение и команды. Покупка, продажа, погрузка и выгрузка вызывают `CargoTransferSystem.execute(action, resource_id, quantity)`. Автопилот использует тот же сервис.
- После команды: вернуть `{ok, message}`, сохранить состояние и сообщить через EventBus, если есть подписчики.
- Неизвестный ID сохранённого корабля останавливает загрузку с сообщением; он не заменяется бесплатно лодкой и не уничтожает сохранение.

## Проверка изменений

`tests/run_tests.sh` запускает тесты с временным каталогом пользовательских данных. Не запускать тестовые сцены на игровых сохранениях. Проверяются каталоги, зависимости модулей, сохранения, физика, торговля, ранги, челленджи, награды и полная сцена.

При изменении JSON сначала исправить сообщения проверки конфигурации. При добавлении механики проверить не только успешный путь, но и отказ без потери денег/товара, повторное действие и загрузку сохранения. Отображение в Windows остаётся отдельной ручной проверкой.
